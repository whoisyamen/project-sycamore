## Benchmark implementation recipe

Use Python standard library, matching the current ingestion test style.

1. Import runner/rss_client with the package root configured the same way as
   tests/test_pipeline.py.
2. Create independent source fixtures from that test's ARTICLE shape.
3. Use tempfile.TemporaryDirectory for each scenario.
4. Patch rss_client.fetch_all and to_articles with fixed batches.
5. Patch runner._osint_cycle to return [] and media_pipeline.attach_media to
   avoid media/network calls. Patch optional GDELT fetch to fail the benchmark
   if invoked unexpectedly. Use use_gdelt=False.
6. Use deterministic clock values for correctness and perf_counter for duration.
7. Run the actual runner.run(temp_path), validate the resulting snapshot,
   collect duration/bytes/counts/health/IDs, then allow temp cleanup.
8. Deliberately unexpected network access must fail rather than fetch live data.
9. Write only beneath the explicitly supplied report directory, not fixture output
   into public/data. If --out resolves to public/data or contains a live snapshot,
   reject it.

Cases:
- identical source repeated: one numeric ID, no extra event;
- same URL/revised title: document CURRENT behavior (same event, revised text
  may be ignored); do not implement revision handling yet;
- two outlets/same story: merged sources, one event;
- partial provider failure: degraded, successful-check semantics retained;
- total failure after success: previous events/lastSync retained;
- successful empty response: valid health state;
- pruning/high-water test: old ID not reused;
- snapshot-only fixture migration: no fetch and no invented successful sync.

Use 500 and 5,000 synthetic source records for scale measurements when practical,
each explicitly marked synthetic. The current live projection is capped at 500.
Do not claim 5,000 records are archived by today's code.

## Producer/consumer map template

Fill each row with actual symbol and file line, plus the invariant at risk.

| Boundary | Producer | Consumer | Contract / failure risk |
| --- | --- | --- | --- |
| Numeric ID / nextEventId | runner allocation | routes/state/selection/validation | Link break or ID reuse |
| Deduplication | normalizer.dedupe_key + URL set | runner merge | Same report vs event identity |
| V1 snapshot | runner._publish | loader/refresh/site | Strict schema and latest-state selection |
| Compatibility mirrors | publisher after snapshot | identify actual readers | Partial write vs canonical state |
| Geolocation | normalizer / runner validation | globe marker and detail copy | Approximate location presented as exact |
| Source health | source batch + run | status UI | Attempt mistaken for success |
| Independent telemetry | _osint_cycle and browser sources | globe/osint client | Layer stale state vs event freshness |
| Served data | local public/dist and deployment mechanism | real browser/CDN | Local success is not served freshness |
