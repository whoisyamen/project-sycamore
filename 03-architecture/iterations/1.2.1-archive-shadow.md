## Repository behaviors (implement with explicit return types)

- import_snapshot(snapshot, import_identity): return stable numeric-ID-to-UID map;
  repeat import returns existing mapping, never new UUIDs.
- record_batch(run_uid, provider_results, observed_at): store source observations
  and source revisions; retry with same run/input does not duplicate rows.
- record_event_revision(event_uid, evidence_refs, normalized_content): append only
  if semantic content changes; clocks alone do not append a material revision.
- compare_projection(legacy_snapshot, candidate_snapshot): compare events, ID map,
  sources, counts and relevant health with fixed clocks; emit differences.
- record_shadow_gap(run_uid, reason): make missing coverage visible to the operator.

Names are proposed function names; keep them unless a baseline conflict is
documented. Do not return loose dictionaries with undocumented fields everywhere.

## Required tests

| Scenario | Setup/action | Required result |
| --- | --- | --- |
| Initial import | Copy snapshot IDs 1 and 99, nextEventId 100 | Mapping stored; next ID ≥100 |
| Repeat import | Same import identity and bytes twice | Same UIDs/counts |
| Pruned report returns | Store >500 records, then reobserve oldest URL | Same source/event identity, not new ID |
| Changed article | Same provider/URL, changed source title/lede | New source revision, old revision retained |
| Identical re-fetch | Same content in next run | New observation; no duplicate content revision |
| Same-run retry | Replay run_uid and batch | No extra observation/revision |
| Publisher vs provider | Two sources citing same report | Separate observations; no automatic independent-evidence claim |
| Missing geolocation | Valid report without safe map position | Internal record retained; no fabricated v1 marker |
| Invalid URL/payload | Malformed fixture | Reject/record reason; no unsafe public content |
| DB transaction error | Inject error before commit | No partial archival rows; legacy JSON path continues in shadow |
| Shadow gap | Failed archive then later successful cycle | Gap retained; not labeled continuous history |
| FK constraint | Dangling evidence reference | Transaction fails |
| Migration replay | Apply twice; then change checksum | Second application no-op; changed checksum rejected |
| Output parity | Fixed batch/clocks with legacy vs shadow | Identical v1 behavior and numeric IDs |

Live and synthetic data are distinct. Capacity for 90 days is a load result, not
proof that 90 days of actual reports have been collected.
