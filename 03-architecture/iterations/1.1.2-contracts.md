## Required fixture set and assertions

| Fixture | Action | Expected |
| --- | --- | --- |
| Existing v1 record | Old and current snapshot validator | Both accept, unchanged serialized keys |
| V1 + eventUid | Old/current v1 validator | Reject extra property; this proves why enrichment is separate |
| Valid intelligence detail | Both new validators | Accept identical meaning and IDs |
| Unknown detail property | Both validators | Reject |
| Arbitrary $ref path/URL | Registry resolution | Reject; no filesystem escape or network access |
| Event ID 17 mapped to UID A | Import/replay identity helper | Reuse A; changed title retains A |
| Two identical URLs, different provider | Source-key helper | Distinct source identities; not two automatic incident identities |
| URL fragment/default port variation | Canonicalizer | Equivalent as specified; original URL retained |
| Two meaningfully different query strings | Canonicalizer | Distinct; no global query stripping |
| Unicode/non-BMP and fraction | Python + JS canonical hash | Same SHA-256; reject non-finite numbers |
| Malformed/oversize array/string | New validators | Reject with safe failure |
| Changed revision/source field | Projection/content hashes | Expected differing hash, clock-only semantic change excluded |
| Artifact with missing evidence target | Referential checker | Reject dangling reference |
| Artifact with wrong event/release UID | Reader consistency helper | Reject even if schema alone accepts |
| Invalid generated script | CSP/artifact checks | No dynamic evaluation introduced |

Record schemas represent allowed record data; foreign keys, stable import mapping
and persistence are verified end-to-end in 1.2.1. Do not claim a stateless helper
alone proves persistence.
