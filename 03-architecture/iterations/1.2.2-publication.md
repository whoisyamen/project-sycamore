## Configuration contract

- `mode` gains value 'archive' alongside legacy|shadow; default remains legacy.
  Invalid modes are rejected before any I/O (existing ValueError path).
- Archive mode requires the same explicit --archive guard as shadow: resolved
  path must be outside g3-astro/public and dist, parent dir writable — validated
  before fetch. Do not guess a private path.
- Bootstrap rule (fail-closed): an archive-mode cycle may derive its previous
  state only from (a) the latest published publication_jobs payload if any exists,
  or (b) events carrying an import_identity (full legacy-import payloads). A DB
  with neither — i.e., live-ingest-only revisions and no prior publication — must
  raise before fetch. Cutover therefore begins by importing the current snapshot
  into the archive under a stable identity; that procedure is documented in the
  README/ADR, not silently invented at runtime.

## Repository behaviors (implement with explicit return types)

- Archive.latest_projection() -> dict | None: {'events': list[dict], 'manifest': dict}
  from the highest-sequence published payload; else reconstructed full events from
  current legacy_import revision payloads + manifest rebuilt per _empty_manifest rules.
  Returns None when no committed state exists at all (fresh DB, nothing imported).
- Archive.transaction() -> context manager yielding the shared connection inside an
  explicit BEGIN IMMEDIATE ... COMMIT/ROLLBACK transaction; nested public methods must
  not be called from within it — use *_tx helpers instead.
- publisher.commit_cycle(...) -> dict: {'publication_uid': str, 'sequence': int}.
- publisher.replay() -> list[int]: sequences actually (re)written this call, ascending.
- publisher.sync_mirrors() -> bool: True when any file was rewritten or verified-missing-repaired.

| Scenario | Setup/action | Required result |
| --- | --- | --- |
| Before DB commit | Inject exception inside the commit transaction after some writes | Full rollback: zero new source_records/observations/revisions/run rows; snapshot.json byte-identical to previous cycle |
| After DB commit, before file replace | Commit succeeds; patch file write to raise once during replay | Job stays pending with attempts incremented; re-running publisher.replay() publishes the payload without any provider fetch (fetch call count unchanged) |
| Snapshot replaced, before acknowledgement | Ack step patched to fail after all three files written | Repeating the job is harmless: identical bytes on disk, hash verified against stored payload_hash, no duplicate publication state corruption |
| Mirror write fails / mirrors diverge | Delete events.json + manifest.json post-publish; run sync_mirrors() or a new archive cycle start | Mirrors rewritten from committed payload; canonical snapshot never regressed to older content |
| Multiple pending jobs | Two+ commits with replay suppressed, then one real replay | Files written in strictly increasing sequence order (writer spy asserts monotonic lastSync); final file equals highest-sequence payload exactly |
| Total source failure | fetch_all raises in archive mode | Previous committed events retained; manifest.lastSync unchanged, lastAttempt advanced, health.status error + failedSources recorded; ingest_runs row outcome=error inside the same transaction as the publication job |
| Enrichment (media) fails | attach_media patched to raise | Cycle still publishes previous-compatible projection with no new media; failure does not block snapshot/mirrors or DB commit |
| Disk full / write error mid-publish | _atomic_write path patched to raise OSError on first attempt only | Last-good snapshot.json untouched byte-for-byte; job remains pending, retryable after unpatching and replaying (actionable error surfaced) |
| No lost committed events across crashes | 3 fixture cycles adding distinct articles + one title-revision cycle with crash injections at each boundary | Every article ever committed exists in the DB with a stable legacy_id forever; latest file reflects all non-pruned commits; re-observing an old URL never allocates a new ID or duplicates content |
| No ID reuse / counter monotonicity | Same fixture set plus bootstrap import of IDs {1..50} then live archive cycles | Next allocated IDs strictly increase across commit, crash and replay sequences; imported high-water honored (no allocation below nextEventId) |
| Bootstrap guardrail | Fresh DB with only live-ingest revisions, no publication, no import identity | Archive-mode run raises before fetch with an explicit error naming the required bootstrap step |
| Config guardrails (archive) | mode='archive' without path / under public data / invalid mode string | ValueError before any file or network I/O, same contract as shadow tests |
| Migration replay + checksum drift | Apply 002 twice; then mutate applied bytes and reopen | Second apply no-op; mutated checksum rejected with the existing error type |

- `publisher.replay(...) -> list[int]` ascending sequences (re)written this call.
- `publisher.sync_mirrors(...) -> bool` True when any file missing/divergent was
